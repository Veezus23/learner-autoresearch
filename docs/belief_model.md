# Belief Model

Version: 0.2

---

# Purpose

The belief model represents the learner's internal understanding of concepts.

Unlike mastery or confidence, beliefs describe **what the learner currently
thinks is true**.

A learner's observable behavior is generated by activating one or more beliefs
during reasoning.

The belief schema is fixed.

The belief library and symbolic rule definitions are fixed.

Per-learner belief strengths, confidence values, and activation history may
change through fixed learner-update rules.

Autoresearch may not modify the belief schema, belief library, symbolic rule
definitions, or update rules.

---

# Design Philosophy

This project separates

Objective Knowledge

Belief Library

Learner Belief State

Behavior

A learner is not defined by correctness.

A learner is defined by the beliefs they use when reasoning.

The language model expresses these beliefs but does not create them.

---

# Why Beliefs?

Incorrect answers arise for different reasons.

A learner may

- possess an incorrect rule
- possess multiple competing rules
- possess incomplete knowledge
- possess no usable rule

These situations produce different learning behavior.

Representing beliefs explicitly allows the system to distinguish these cases.

# Belief Library

The belief library is a fixed catalog of possible beliefs.

Each library entry is a `BeliefDefinition`.

`BeliefDefinition` contains:

- `belief_id`
- `concept_id`
- `belief_type`
- `transformation_id`
- `prerequisite_concept_ids`
- `description`
- `version`

The belief library does not contain learner-specific strength, confidence, or
history.

The belief library owns semantic distinctions such as correct, misconception,
partial, and unknown.

The evaluator may detect behavior, but the evaluator does not define belief
type.

---

# Learner Belief State

Learner belief state is a learner-specific record referencing library beliefs.

Each learner belief record is a `LearnerBelief`.

`LearnerBelief` contains:

- `belief_id`
- `current_strength`
- `belief_confidence`
- `status`
- `evidence_count`
- `last_activated_turn`
- `activation_count`

`LearnerBeliefState` is a concept-grouped collection of `LearnerBelief`
records.

Learner belief state may change over time through fixed update rules.

For V0, `status` is one of:

- `active`
- `inactive`
- `retired`

Learner belief state is the single source of truth for belief strength,
misconception strength, belief confidence, belief status, and belief activation
history.

`active_misconceptions` and `misconception_strength` are derived views, if
needed, over learner belief state records whose fixed library type is
`misconception`.

Learner state may retain the last activated belief ID in interaction history,
but it does not own permanent misconception definitions.

---

# Belief Definition

A belief is a symbolic representation of a rule, interpretation, or hypothesis
that the learner currently treats as true.

Beliefs are associated with concepts.

Examples

Correct

PowerSet(S) -> AllSubsets(S)

Misconception

PowerSet(S) -> S

Partial

PowerSet(S) -> AllNonEmptySubsets(S)

Unknown

No usable transformation exists.

---

# Multiple Competing Beliefs

A learner may simultaneously possess multiple beliefs regarding the same
concept.

Example

Concept

power_set

Beliefs

Correct

current_strength = 0.35

Misconception

current_strength = 0.80

Partial

current_strength = 0.45

Unknown

current_strength = 0.10

The learner policy later decides which belief becomes active during reasoning.

This allows inconsistent behavior without randomness.

---

# Belief Types

Each belief belongs to one of four categories.

## Correct

Represents a correct symbolic rule.

Correct beliefs should become stronger through successful practice via fixed
learner-update rules.

---

## Misconception

Represents a structurally incorrect rule or interpretation that may be
internally consistent.

Misconceptions are not random mistakes.

The misconception distinction is semantic and belongs to the fixed belief
library, not the evaluator.

---

## Partial

Represents a structurally incomplete rule that is directionally aligned with the
correct concept.

The learner understands part of the concept but not all of it.

Partial beliefs may still generate incorrect answers.

Example

Power set excluding the empty set.

The partial distinction is semantic and belongs to the fixed belief library, not
the evaluator.

---

## Unknown

Unknown is a sentinel belief type.

It represents the absence of a usable rule.

Unknown has no executable symbolic transformation.

For unknown beliefs, `transformation_id` identifies the sentinel absence of an
executable transformation.

Unknown has learner-specific strength and confidence.

There is at most one unknown belief per concept.

Unknown activation may lead to

- guessing
- requesting hints
- abstention
- incomplete reasoning
- uncertainty

---

# Belief Strength

Belief strength is stored in learner belief state as `current_strength`.

Belief strength represents

How likely is this belief to become active when the associated concept is
encountered?

Strength

0.0

belief never activates

1.0

belief almost always activates

Belief strength is learner-specific and may change only through fixed
learner-update rules.

---

# Confidence

The architecture distinguishes three confidence levels.

## Concept Confidence

Concept confidence is stored in learner state.

It represents the learner's general confidence for a concept.

## Belief Confidence

Belief confidence is stored in learner belief state.

It represents trust in one specific belief.

Belief confidence is not belief strength.

## Expressed Confidence

Expressed confidence is produced by the policy for one interaction.

For V0, expressed confidence should be derived from concept confidence,
activated-belief confidence, and interaction context.

The exact formula is not defined yet.

Example

A learner may strongly activate an incorrect belief while expressing high
confidence.

Another learner may activate the correct belief while expressing low confidence.

---

# Beliefs and Mastery

Mastery represents learning progress.

Beliefs represent internal knowledge.

These are different.

V0 rule:

- topic mastery does not directly select a belief;
- prerequisite mastery affects prerequisite support;
- belief strength and prerequisite support affect activation;
- mastery may influence belief strengths only through fixed learner-update
  rules after interactions;
- high mastery may correlate with strong correct beliefs, but policy activation
  must still occur through the belief model.

---

# Prerequisite Support

Every belief may depend on prerequisite concepts.

Example

Correct Power Set belief

requires

- set_notation
- subsets

If prerequisite mastery is weak,

the effective activation support for the belief decreases.

Misconceptions may require different prerequisite support.

# Belief Activation

Beliefs are not permanently active.

During each interaction, the learner policy evaluates competing learner belief
records.

For V0:

- activation is deterministic;
- only beliefs with active status are candidates;
- candidates receive the fixed V0 baseline activation score;
- the belief with the highest score is selected;
- interaction context affects action selection, not V0 activation;
- probabilistic sampling is deferred to future work.

For each active candidate belief `b`:

`A(b) = 0.40*S + 0.25*C + 0.25*P + 0.10*R`

Where:

- `S` is current belief strength in `[0, 1]`, including any fixed
  one-interaction effective `current_strength` boost generated by learner-update
  rules.
- `C` is learner-specific belief confidence in `[0, 1]`.
- `P` is prerequisite support in `[0, 1]`.
- `R` is normalized recency in `[0, 1]`.

Unknown beliefs use `P = 1.0`.

The V0 activation formula inputs are limited to:

- current belief strength
- belief confidence
- prerequisite support
- recency

Ties are broken by:

1. greater prerequisite support;
2. greater belief strength;
3. lexicographic `belief_id` for reproducibility.

This formula is the fixed V0 baseline. Future changes require human approval
unless a later architecture version explicitly moves the activation formula into
the autoresearch policy boundary.

The temporary relevant correct-belief boost after a hint is a fixed
learner-update effect defined in [learner_model_spec.md](learner_model_spec.md).
It does not persist to `LearnerBelief.current_strength`.

---

# Interaction Context

Policy-visible interaction context is bounded.

Allowed:

- attempt number
- whether a hint is available
- whether learner-facing feedback was received
- prior learner answer text
- prior action
- recent activated belief IDs
- bounded interaction history

Forbidden:

- evaluator correctness judgment unless presented as learner-facing feedback
- detector outputs
- behavioral-fidelity scores
- validation aggregates

---

# Interaction with Learner State

Beliefs never replace learner state.

Learner state stores

- mastery
- concept confidence
- persistence
- hint tendency
- guess tendency
- interaction history

Learner belief state stores

- current belief strength
- belief confidence
- belief status
- evidence count
- activation history

---

# Interaction with Learner Policy

The learner policy does not invent knowledge.

Instead,

it

1. observes policy-visible learner state and learner belief state;

2. evaluates competing beliefs;

3. activates one or more beliefs;

4. produces a behavior plan.

The behavior plan contains:

- `activated_belief_id`, or no belief
- `action`: `answer`, `guess`, `request_hint`, `abstain`, or `revise`
- `expressed_confidence`
- persistence decision
- optional reasoning mode

The policy must not directly choose "correct" or "incorrect."

Correctness is an observable consequence of applying the activated belief, not
a direct policy field.

The policy does not define symbolic rules.

The policy may access correct symbolic belief rules from the fixed belief
library.

A correct symbolic rule is not the same as a benchmark answer key.

The policy must not access case-specific correct answers, expected outputs,
evaluator labels, or validation expectations.

Symbolic rules should be concept-level and reusable across many questions.

---

# Interaction with Language Generation

The language model receives

Question

+

Activated beliefs

+

Behavioral plan

Natural language response

The language model is an expression engine.

It is not the learner.

The expression layer must verbalize the selected behavior plan and activated
belief.

It must not independently solve the question.

It must not repair, override, enrich, or replace the activated belief using
external correctness.

If it cannot express the plan faithfully, it should return a generation failure
rather than correct the learner.

---

# Learning

Learner belief state changes gradually through fixed update rules.

Correct practice

Strengthens correct beliefs.

Corrective feedback

Weakens misconceptions.

Hints

Temporarily increase activation of relevant correct beliefs.

Repeated failure

May increase unknown beliefs or hint tendency.

Autoresearch may not modify the belief schema, belief library, symbolic rule
definitions, or update rules.

---

# Information Boundaries

Beliefs never contain

- evaluator labels
- benchmark expectations
- hidden test information
- scoring weights
- validation answers

Beliefs represent cognition only.

The policy may access correct symbolic belief rules from the fixed belief
library.

The policy must not access case-specific correct answers, expected outputs,
evaluator labels, validation expectations, or hidden test metadata.

# Future Extensions

The belief model is intentionally minimal.

Future work may include

- probabilistic graphical beliefs
- prerequisite reasoning graphs
- belief decay
- forgetting
- concept transfer
- belief revision
- Bayesian belief updates
- neuro-symbolic representations

without changing the surrounding architecture.

Probabilistic sampling is deferred to future work.
